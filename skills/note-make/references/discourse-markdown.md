# Discourse Markdown 兼容性

Discourse 使用 CommonMark，并支持一部分 GFM 扩展。笔记默认是私人笔记，读者是用户自己；这份文件只约束格式，不改变写作风格、解释深度或读者假设。笔记先在本地保存，之后如果要贴到 self-hosted Discourse，按下面的子集写作最稳。

## 可以放心使用

- 标题：`#` 到 `######`，不要跳级。正文通常只用一个 `#` 标题，章节用 `##`。
- 段落：块之间空一行。
- 列表：`-` 或 `1.`，列表前后空一行。嵌套列表用 2 或 4 个空格缩进，保持一致。
- 引用：`>`。
- 围栏代码块：以三个反引号开头并标注语言（如 `bash`、`sql`、`yaml`），以三个反引号结束。
- 行内代码：用单个反引号包住，例如 `code`。
- 表格：标准 GFM 表格，必须有表头行；不要合并单元格。
- 链接：`[文字](https://...)` 或裸 URL。
- 图片：`![alt](https://...)`，图片必须已经上传到 Discourse 或可公开访问的 URL。
- 粗体 / 斜体：`**粗体**`、`*斜体*`。少用。
- 删除线：`~~文字~~`。
- 分隔线：单独一行 `---`。不要放在文件开头，避免被误读为 frontmatter。
- Emoji：`:smile:` 或直接使用 Unicode emoji。
- 数学公式：仅在目标论坛启用 MathJax 时使用。行内公式写成 ` $...$ `，前后各留一个半角空格（紧贴中文或标点时也要留；行首/行尾可省略）。`$$...$$` 独占一行，前后空行。代码块和行内代码里的 `$` 不参与公式。

## 不要使用

- YAML frontmatter（用 `---` 包起来的元数据）。Discourse 不会解析，可能显示成正文或分隔线。
- 原始 HTML（`<div>`、`<br>`、`<details>` 等）。会被清理或产生不可预期的结果。散文中的占位符（如 `<token>`）必须用行内代码包住，否则也可能被当作未知标签清理；代码块内不受影响。
- 脚注 `[^1]` 和脚注定义。很多 Discourse 实例不渲染。
- GitHub 警告块 `> [!NOTE]`。Discourse 不识别。
- 任务列表 `- [ ]` / `- [x]`。可能按普通列表显示，丢失勾选语义。
- `==高亮==`、`[[wiki 链接]]`、`:::` 容器、目录宏 `[TOC]`。
- 相对链接（`./file.md`、`../assets/x.png`）。发布后指向论坛域名，通常 404。
- 本地图片路径。Discourse 需要先上传图片。
- Mermaid（语言名为 `mermaid` 的代码块）仅在目标论坛启用对应插件时使用；不确定就用文字或代码。

## 结构建议

- 正文开头可以用一段话给出结论或目的，不一定要先写“背景”。
- 标题层级：`#` 标题 → `##` 章节 → `###` 子节。不要从 `#` 直接跳到 `###`。
- 代码块和表格前后各空一行；否则部分解析器会把它们并进上一段。
- 长代码块按步骤拆分，每块只做一件事；不要把命令和输出混在同一块里。
- 表格列数控制在 3–5 列；列太多在移动端很难读。
- 需要强调时优先用句子结构和位置，而不是连续加粗。

## 贴到 Discourse 前的格式检查

- 没有 YAML frontmatter。
- 没有原始 HTML、脚注、任务列表、GitHub 警告块。
- 所有链接都是完整 URL。
- 所有图片都是可访问的 URL 或已上传。
- 代码块都标注了语言，且命令和输出分开。
- 标题层级没有跳级。
- 行内公式前后有空格；`$$...$$` 独占一行并前后空行。
- 散文中的占位符都用行内代码包住。
- 正文一级标题与 Discourse 主题标题不重复；如果重复，发布时删掉正文的一级标题。
